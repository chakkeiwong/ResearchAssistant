## Phase Objective

Place reviewed production source-status and capped public source/PDF/full-text
transports behind the mission state machine, producing mission-local,
versioned, hash-bound source records and checked anchor candidates while
preserving unavailable, rights, quarantine, retraction/erratum, parser, and
source-gap outcomes.

Parser output and source availability are not claim correctness or support.

## Entry Conditions Inherited From M20

- M20 supplies current lineage-valid selected real candidates and complete
  request/attempt/omission ledgers.
- Candidate identity ambiguity relevant to source selection is either resolved
  under exact authority or remains a blocking disposition.
- M20 result/review and the identified commit are frozen.
- No source/status/PDF/full-text action is authorized by M20 approval.

## Mandatory Refresh Gate

Before implementation or retrieval, the refreshed plan must bind:

- exact selected candidates and identity/version requirements;
- allowed domains, routes, methods, artifact/MIME types, licenses/rights,
  robots/terms handling, request/redirect/retry/time/byte/file/source caps;
- retention, privacy, quarantine, malware/content-safety, cache, and deletion
  policy;
- exact `MissionSourceCapability` production adapters and separation from
  existing general fetch/download commands;
- source version, hash, provenance, erratum/retraction, accessibility, parser,
  and anchor-location schemas;
- exact no-network/recorded-response tests, source/PDF/full-text live matrix,
  commands, output roots, and fresh approval packet; and
- proof that all adapter/parser execution bytes equal the identified M20 commit
  or an exact reviewed Git procedure, approval, successor commit, and isolated
  clean-install gate before source use; and
- which claims/sections/equations/theorems are only anchor candidates for M22,
  never automatically supported.

The plan must receive rights/privacy/boundary audit and fresh read-only
agreement. The user must then approve the exact frozen source action; ordinary
M20 development approval is insufficient.

## Exact Edit And Write Allowlist

This shell authorizes no edit or source action. The refreshed plan must list
every adapter, schema, parser integration, test, sanitized fixture, CLI,

## Exact Next-Phase Handoff Conditions

M22 may enter refreshed planning only when each attempted selected source has a
closed outcome; admitted source bytes/versions/provenance and anchor candidates
are hash/location-bound; all rights/privacy/quarantine/gap states are visible;
no parser output is mislabeled reviewed support; pre-confirmation no-call and
post-confirmation no-extra-prompt gates pass; execution bytes are tied to an
identified clean commit; cumulative gates and final review pass; and M22 is
refreshed with exact review queues, source anchors, mission matrix candidates,
genuine reviewer roles, conflict/privacy/correction policy, operator workflow,
and human-action approval requirements.

## Stop Conditions

Stop for unclear rights/privacy/retention, unapproved access, unestablishable
required source version, inability to preserve auditable source location,
unsafe/unrepresentable content, corrupt harness/artifact, criteria changes after
results, or five-round nonconvergence. An unavailable source, parser failure,
or missing anchor is an honest source-gap result and planned repair trigger,
not a program stop when the boundary and artifact remain valid.

records, anchors, gaps, and human boundaries; review M22 for consistency,
correctness, feasibility, artifact coverage, inherited conditions, privacy,
